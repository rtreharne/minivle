Scoped Canvas compatible API

A launch bound REST API for LTI 1.3 tools. It provides Canvas shaped course, user, assignment, submission, rubric, association, and assessment resources using MiniVLE data.

Base URL: {{ origin }}. API paths below are relative to this origin. All resource calls require HTTPS in deployed environments and a bearer token obtained for the current LTI launch.

How the flow works

  1. The user launches the registered tool through an LTI 1.3 resource link.
  2. The tool validates the signed LTI id_token as usual and retains it briefly for the exchange.
  3. The tool obtains a MiniVLE bearer token by signing a client assertion with its registered private key.
  4. The tool calls the approved API routes with Authorization: Bearer ….

This is client credentials grant syntax with a launch context extension. It is not Canvas OAuth and does not provide a Canvas access token. The bearer token expires after five minutes, is bound to the launch user, tool, deployment, launch course, resolved course set, role, and approved scopes, and must not be shared between users or launches.

Exchange a launch for a bearer token

Send a form encoded POST to /lti/token/. The client assertion is an RS256 JWT signed by the tool private key matching the public JWKS configured for its registration. Its audience is the full token URL; iss and sub are the tool client ID, and it includes unique jti, iat, and exp claims. Assertion lifetime may not exceed five minutes.

POST /lti/token/ HTTP/1.1
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials&client_assertion_type=urn:ietf:params:oauth:client-assertion-type:jwt-bearer
&client_assertion=eyJ...tool-signed-jwt...
&launch_token=eyJ...platform-signed-LTI-id-token...
&scope=url%3AGET%7C%2Fapi%2Fv1%2Fcourses%20url%3AGET%7C%2Fapi%2Fv1%2Fusers%2Fself

URL encode form values using your HTTP library. The signed launch token must be a valid, unexpired Resource Link launch for the same client and deployment. Each launch token and each client assertion jti may be exchanged once.

{"access_token":"…","token_type":"Bearer","expires_in":300,"scope":"url:GET|/api/v1/courses url:GET|/api/v1/users/self"}

Example resource request:

GET /api/v1/courses HTTP/1.1
Authorization: Bearer <access_token>
Accept: application/json

Configure method and path scopes

A platform administrator configures an allowlist on the LTI tool registration detail page under Canvas-compatible API, one scope per line. The tool requests only the subset it needs during exchange. Scopes use this exact form and canonical route templates (the variable names are significant):

url:<METHOD>|/api/v1/<route-template>

For example, the list call is url:GET|/api/v1/courses. A scope mismatch, unregistered scope, or scope removed from the registration denies the call. The server checks the method and route scope on every request; changing an allowlist can invalidate access before the token expires.

Course discovery and access

GET /api/v1/courses returns courses in the token’s launch course set. MiniVLE resolves this set at exchange by traversing from the launch course through users with active enrollments, following every active role, until no further courses are found. Inactive enrollments are ignored; the resulting set stays fixed for the token lifetime. Platform administrators receive all courses.

GET /api/v1/users/self returns the launch user. Learners can read their own submissions and grades. Instructor launches can read student records in reachable courses. Platform administrators can access student records in any course. Course IDs outside the bound set return not found. Writes require the corresponding scope and course management authority; a learner may submit their own work and upload their own submission file. Admin users can manage across courses.

Resource routes

Courses and user

  • GET /api/v1/courses: paginated courses, fields include id, name, course_code, and workflow_state.
  • GET /api/v1/users/self: current user fields include id, name, short_name, sortable_name, login_id, and email.

Assignments

  • GET /api/v1/courses/:course_id/assignments: list assignments; accepts include[]=rubric.
  • POST /api/v1/courses/:course_id/assignments: create assignment.
  • GET|PUT|PATCH|DELETE /api/v1/courses/:course_id/assignments/:id: read, edit, or delete assignment.

Assignment body can be sent as {"assignment":{"name":"Essay","description":"Instructions","points_possible":20,"published":true,"due_at":"2026-12-01T23:59:00Z","submission_types":["online_upload"]}}. Supported fields are name/title, description, points_possible, published, due_at, and submission_types. Submission types map to MiniVLE file upload or external tool modes.

Submissions and grades

  • GET|POST /api/v1/courses/:course_id/assignments/:assignment_id/submissions: list submissions or submit a learner’s file.
  • GET|PUT|PATCH /api/v1/courses/:course_id/assignments/:assignment_id/submissions/:user_id: read a submission or post a grade and comment. Use self as user ID for the token user.
  • GET /api/v1/courses/:course_id/assignments/:assignment_id/submissions/:user_id/history: list attempts.
  • GET /api/v1/courses/:course_id/students/submissions: list course submissions. Optional repeated student_ids[], assignment_ids[], include[], and grouped=true.

Submission JSON includes status, timestamps, attempt, attachments, score, grade, grader, grade time, and feedback from MiniVLE submission and grade records. Supported includes are assignment, course, user, submission_history, rubric_assessment, and full_rubric_assessment. Grading accepts {"submission":{"posted_grade":18,"comment":"Good work"}}; score is accepted in place of posted_grade.

Rubrics and assessments

  • GET|POST /api/v1/courses/:course_id/rubrics: list or create rubrics.
  • GET|PUT|PATCH|DELETE /api/v1/courses/:course_id/rubrics/:id: read, update, or delete. GET supports include[]=associations, include[]=graded_assessments, or include[]=peer_assessments; assessment includes accept style=full or style=comments_only.
  • GET /api/v1/courses/:course_id/rubrics/:id/used_locations: list course and assignment references.
  • POST /api/v1/courses/:course_id/rubric_associations: create association.
  • PUT|PATCH|DELETE /api/v1/courses/:course_id/rubric_associations/:id: update or delete association.
  • POST /api/v1/courses/:course_id/rubric_associations/:rubric_association_id/rubric_assessments: create a criterion-level assessment.
  • PUT|PATCH|DELETE /api/v1/courses/:course_id/rubric_associations/:rubric_association_id/rubric_assessments/:id: update or delete assessment.

A rubric body uses rubric.title, rubric.free_form_criterion_comments, rubric.hide_score_total, and rubric.criteria (the Canvas data alias is also accepted), with criteria holding IDs, descriptions, points, and ratings. A rubric association accepts rubric_id, association_id, association_type (Assignment or Course), use_for_grading, hide_score_total, and purpose. Assessments accept user_id, assessment_type, total score, criterion keyed data, comments, and provisional/final flags. A final grading assessment on an association marked use_for_grading updates the corresponding grade.

Writes accept JSON or bracketed form fields and generally use a Canvas wrapper (assignment, submission, rubric, rubric_association, or rubric_assessment). Creates return 201; successful reads and updates return 200; deletes return the deleted representation.

Submission file upload

For Canvas style two step upload, POST metadata to /api/v1/courses/:course_id/assignments/:assignment_id/submissions/:user_id/files with name, size, and optional content_type. This returns a temporary upload_url and upload_params. POST multipart field file to that URL; the upload authorization is single use, must match the declared size, expires after 15 minutes, and files are limited to 100 MB. Follow the 303 redirect and GET the completion URL with the same bearer token. The completion response contains the file ID, URL, display name, filename, and size. The API also accepts a direct multipart file on the scoped /files route, then that file can be submitted with the assignment submissions POST. Uploads are limited to the launched learner’s own active course enrollment.

Formats, pagination, and errors

Responses are JSON. Send JSON request bodies with Content-Type: application/json; bracketed form keys such as assignment[name] are also accepted. For routes that return lists, page defaults to 1 and per_page defaults to 10 and is capped at 100. Responses include a Canvas style Link header with current/first/last and applicable next/previous links. List routes accept repeated or comma-separated-as-supported Canvas query parameters; arrays are commonly sent as include[]=…, student_ids[]=…, and assignment_ids[]=…. Request Accept: application/json+canvas-string-ids to stringify ID fields.

Errors use {"errors":[{"message":"…"}]} for resource requests. Missing or expired bearer credentials return 401; insufficient scope also returns 401; forbidden role actions return 403; resources outside the token course set or invisible to the caller return 404; invalid parameters return 400. Token exchange returns OAuth style {"error":"…"} errors.

This API documents the implemented method/path subset above. It does not expose unrelated Canvas resources, Canvas OAuth user consent, or every optional field and behavior of Canvas. Tools should rely only on the routes, fields, parameters, and behaviors listed here.
